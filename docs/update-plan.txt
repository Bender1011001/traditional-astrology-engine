* *Output:* Raw vectors (Planets, Houses, Stars, Eclipses). No interpretation, just physics.


2. **Mechanics Layer (`mechanics.py`)**:
* *Input:* Raw vectors.
* *Output:* Derived Data (Aspects, Dignities, Lots, Almutens, Primary Directions, Profections). This merges your `advanced_`, `classical_`, and `prediction` logic.

* *Input:* Derived Data.
* *Output:* The **Unified State**. This applies the logic rules (Bonatti, Valens) to flag conditions like "Besiegement" or "Void of Course".


4. **The Product (`models.py`)**:
* The result is **one massive JSON object** that powers the entire UI.

### 3. What the Practitioner Wants (The Product)

A practitioner doesn't want a "calculator." They want a **Digital Sanctum**. Here is the feature set for the dashboard:

#### A. Client Management (The Rolodex)

* **Profiles, Not Just Charts:** A generic calculator forgets you. A professional tool remembers that "Jane Doe" is the client, and she has a *Natal Chart*, a *Solar Return 2024*, and a *Horary Question from Tuesday*.
* **Birth Data Security:** Encrypted storage of birth times/places.
* **Session Notes:** A rich-text field attached to every chart to record consultation notes.

#### B. The "Master View" (The Dashboard)

When they open a chart, they shouldn't see just a wheel. They need a command center with collapsible panels:

* **Center:** The Chart Wheel (Visual).
* **Left Panel (The Native):** Core data. Temperament, Almuten, Dignity Scores, Hyleg. The "Who is this?" panel.
* **Right Panel (The Timeline):** Predictive stack. A scrollable timeline showing *current* Profection, *current* Firdaria, and *upcoming* Primary Directions for the next 5 years.
* **Bottom Panel (The Deep Dive):** Tabbed tables for "Lots," "Fixed Stars," "Medical," and "Aspects."

#### C. The "Time Machine" (Transit Bi-Wheel)

The practitioner is rarely looking at the natal chart in isolation. They are looking at **Now vs. Then**.

* **Dynamic Overlay:** A button to instantly overlay the *current real-time transits* on top of the natal chart.
* **The "Jump" Feature:** "Show me this chart on their 40th birthday." The engine instantly calculates the Solar Return and Transits for that date.

#### D. The "Researcher" (Search Tools)

* **Pattern Search:** "Show me all clients with Sun in 12th House" or "Show me everyone with a Mars-Saturn square." This allows the practitioner to learn from their own database.

### 4. Implementation Plan

Here is how we execute this cleanup using your file list:

1. **Database Layer (`db_manager.py` / `models.py`)**:
* Create a `Client` table (Name, Notes).
* Create a `Chart` table (Linked to Client, stores the JSON output).


2. **The Unification Refactor**:
* **Merge:** `horary.py`, `medical.py`, `mundane.py`, `electional.py` are currently standalone. They must become *sub-modules* called by the main `analyzer.py`.
* **Standardize:** Ensure `primary_directions.py` and `prediction.py` output standard JSON dictionaries, not formatted strings.
* **Kill `synthesis.py` (Text Generation):** A practitioner doesn't need a pre-written AI report (that's for end-users). They need *data*. We can keep a `report_generator.py` for exporting a PDF for the client, but the app itself should be visual/data-driven.


3. **UI/Frontend**:
* The current file list shows `src/static/index.html`, etc. We need to upgrade this to a Single Page Application (React/Vue/HTMX) that consumes the massive JSON object and renders the "Master View."



**First Step:** We need to verify what the current API (`src/api/v1/endpoints/charts.py`) is actually returning to see how far we are from the "Everything" JSON. Then we rewrite the backend entry point to return the full payload.
